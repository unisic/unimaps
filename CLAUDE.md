# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**Unimaps** (repo `unisic/unimaps`, GPL-3.0-or-later), a live transit map for Bielsko-Biała (Komunikacja Beskidzka + MZK), Metropolia GZM and 53 other zbiorkom cities. This repo is the **frontend only**: the Leaflet map UI (Svelte 5 + Vite, TypeScript strict, a static build in `out/`). The server (JSON API, GTFS-RT feed, live pollers, connection router; it also serves `out/` in production) is closed source and not part of this repo; production builds and deploys from there, taking this repo's `main` as the frontend. Vite is a build tool and the dev server only; nothing of it runs in production. App identity is Unimaps, but the `kb:*` storage keys keep their names on purpose (renaming breaks user state). README.md (English) is a short overview.

## Commands

```bash
npm run dev          # scripts/dev.mjs: Vite's dev server on HOST:PORT (0.0.0.0:8080, HMR), /api proxied (xfwd) to:
                     #   a server checkout in KB_BACKEND_DIR (default ../unimaps-backend) when it exists, run with
                     #   `cargo run --release` on 127.0.0.1:KB_API_PORT (8081); else KB_API_URL (default https://map.unisic.app)
                     #   PORT=8082 npm run dev when 8080 is taken (Steam's steamwebhelper listens on 127.0.0.1:8080)
npm run build        # vite build (app/*.html -> out/), precompress out/ (.br/.gz, scripts/compress-static.mjs)
npm run lint         # eslint .
npm run typecheck    # svelte-check: tsc over .ts plus .svelte (types and a11y)
npm test             # node --import tsx --test "test/**/*.test.ts": client and lib/shared tests
```

Verification is `npm run typecheck` + `npm run lint` + `npm test` + exercising the running app. CI (`.github/workflows/ci.yml`): job `check` runs the first three plus `npm run build`, job `audit` (also daily) `npm audit --omit=dev --audit-level=high`. `scripts/http-contract.test.ts` pins the HTTP front from outside (needs a running server and live upstreams, so not in `npm test`/CI): `BASE_URL=http://127.0.0.1:8080 node --import tsx --test scripts/http-contract.test.ts`.

**Logic that exists twice.** The browser keeps its own copy of `lib/shared/*.ts` (`alerts`, `cities`, `departures`, `detours`, `fleet`, `gzm-stop-key`, `polyline`); the server implements the same logic. `test/rust-vectors.test.ts` pins the TS side against the server's golden vectors, copied into `test/fixtures/vectors/`: a change to that logic needs the same change on the server and both vector copies updated. `lib/shared/cities.json`, `lib/shared/detours.json`, `lib/mzk-fleet.json` and `lib/phototrans.json` are also compiled into the server: an edit goes into its copy too.

## Architecture

### The API as the client sees it

- Two wire dialects: KB rows in relative minutes (`time_diff` in MINUTES, `time: null` + `at_stop`), MZK and every zbiorkom city (`operator: "GZM"` = the "seconds dialect") as absolute instants with delays in SECONDS. Rows come normalized to epoch seconds (`lib/shared/departures.ts`: `plan_ts`, `eta_ts`, `delay_sec`, `row_key`, `server_ts`); the client resolves ONE canonical ETA per row (`resolveTiming`) for both label and order. A `not_started` row or vehicle never yields a delay from any source.
- Cities: `ZB_CITIES` in `lib/shared/cities.json` (gzm + 53 zbiorkom slugs; `bielskoBiala` absent, BB is native) is the ONE registry, read by `lib/shared/cities.ts`: client `CITY` (generic entries poll vehicles every 10 s, operator logo from `public/logos`; `color` = the logo's main colour at 4.5:1 under white, pinned by `test/zb-cities.test.ts`, absent = slate; `lineColors` overrides single lines), `isCity`, `cityOfId` (the slug before `:` of an id), `OTHER_CITIES`, storage keys via `cityKey(base, city)` (`:<slug>` suffix, BB bare). List routes take `?city=<slug>`; ids carry the slug prefix (`gzm:<stop_id>`, `<slug>:<trip>`).
- A 503 "Data is loading" (a city feed still parsing) is `isWarming`; departures/timetable answers may carry `warnings: ["kb"|"mzk"]` (a failed upstream fetch is not "no departures"); `/api/vehicles` sends `X-Server-Time` and, for zbiorkom cities, `X-Next-Update`; vehicles carry `shape`, `dist_m`, `fix_at`, `next_stop_seq`, `speed`, `sched_speed`, and for KB while upstream's stop index is stale `delay_src` and `geo_seq` (prefer it over `current_stop_sequence` as the `findActiveStop` hint).
### Frontend

`app/` holds the pages: one `<name>.html` per page (`index`, `brygady`, `prywatnosc`, `status`, `404`; listed in `PAGES`, `app/head.ts`, whose `head()` vite.config.ts writes into each at `<!--head-->`) plus its entry script (`app/index.ts` etc., `boot()` in `app/boot.ts` mounts the page component into `#app` and `PwaRegister` into `<body>`). Pages are plain static files: anything per-request is the server's. Svelte 5 runes, client-only (no SSR). `app/index.ts` → `components/MapShell.svelte`, which `import()`s `MapApp.svelte` once a city is chosen, so the Leaflet/MapLibre chunk loads after the picker and in parallel with the first vehicles request. Never import leaflet/maplibre from MapShell or the page entries.

- **City.** `lib/client/city.ts`: a page load shows ONE city, fixed for its life (switching = `location.assign`, so module state keyed at load is safe). `MapShell` resolves it before mounting MapApp: `?city=gzm` or a `gzm:` stop/exec/trip id = GZM, any other app param = BB (old deep links), else the stored `kb:city`, else the picker (shown once; a city from the URL is stored only when nothing is stored yet). BB carries no city marker anywhere: `cityUrl`/`withCity` return BB fetch URLs, URL writes and storage keys unchanged; GZM adds `city=gzm` and suffixes its keys (`stops-gzm` offline copy, `kb:annSeen:gzm`). GZM polls vehicles every 5 s (the SDIP overlay moves a vehicle every ~5 s), BB every 4 s. A zbiorkom city's `/api/vehicles` answer carries `X-Next-Update` (epoch ms its next body is due, `GzmLive::next_body_at()`: SDIP's grid while it runs, else zbiorkom's, absent while the loop is idle); `vehiclesPollDelay()` (`lib/client/api.ts`) maps it onto `performance.now()` and the swr interval fires right after it (250 ms floor, at most 2 x the city's interval, the city's interval when absent or passed), so a poll lands ~1 s after the server's body instead of on a random phase. A 503 "Data is loading" is shown as `GZM_LOADING` (`isWarming`), never cached, and never wipes a list already on screen. TopBar hides Przewoźnik in GZM (no operator filter there); its menu shows the page's city as one row that unfolds the others ("Zmień"). City by location: `cityAt(lat, lon)` (`lib/client/city.ts`, pure) is the nearest centre measured in the city's reach (guessed from its default zoom, at most 40 km), `cityToOffer` returns one only outside the open city's reach. The picker's "Znajdź moje miasto" asks for one coarse fix on tap; MapApp offers the switch as a sticky Toast ("Przełącz") on the first fix of the locate watch, or, when location is already granted, on one coarse `getCurrentPosition` at mount (no watch): once per page load, a declined pair stays in `kb:cityOfferOff`. The tab title is MapShell's `<svelte:head><title>`. An address hit in the search (`onPickPlace`, geocode debounced 350 ms, off after a 404) opens NearbyView around that point (`nearbyPlace`) with a pin.
- `MapApp.svelte` is the single stateful root: no state library; all state flows down as props. API data and objects replaced wholesale are `$state.raw` (a deep proxy would break identity: `vehiclesClock` is a WeakMap keyed by the poll's `vehicles` array). An effect re-runs on EVERY reactive read: read the real deps, wrap the rest in `untrack()`.
- Data fetching: `swr()` (`lib/client/swr.svelte.ts`, the few SWR features the app used: one shared entry per URL, deduping, refresh interval from the latest data, focus/reconnect revalidation, no polling in a hidden tab, backoff, an unchanged payload keeps its identity) only for `/api/vehicles` (4 s poll, the app heartbeat; every 2 s before the first answer and while the server has no good upstream poll yet (`timestamp` 0, at most 3 scans); MapShell `preload`s the first request with the city choice so it overlaps MapApp's Leaflet/MapLibre chunk; `vehiclesFetcher` records receive time + `X-Server-Time` in the `vehiclesClock` WeakMap) and `/api/stops` (ETag-revalidated: on focus (at most once a minute), every 15 min, every 20 s while the body says `partial`: a page that lives for days must not keep a list built while one operator's stops were missing; focus events are ignored during the first `focusThrottleInterval` after mount, hence the intervals). Never destructure an `swr()` result: its fields are getters. Everything else is manual `fetch` with AbortController via `lib/client/api`.
- Trip opening uses generation-counter cancellation (`tripSeq` in MapApp): every async step re-checks `gen !== tripSeq` before assigning state. New async paths there must do the same or stale trips overwrite newer ones.
- `VectorBaseLayer` (MapLibre GL vector tiles from OpenFreeMap inside Leaflet's tile pane; on `style.load` every `name_en` in a label expression becomes `name:pl`, the styles label "Warsaw", and every `poi` symbol layer's filter is ANDed with "subclass not bus_stop/bus_station/tram_stop": the basemap's own stop names collided with our markers; the GL canvas is capped at `pixelRatio` 2 and a touch device keeps 128 tiles instead of 1024: on a phone the cost of a pan is the GPU's fill rate, not the main thread; a `BaseLayer`'s `paint` (layer id -> paint properties, `components/topbar.ts`) is applied there too: `DARK_PAINT` recolours OpenFreeMap's "dark", whose roads and names were near-invisible, with no per-frame CSS filter), `StopsLayer` (raw `L.layerGroup`, viewport-culled and diffed, zoom ≥ 14; a zbiorkom pole carries its post number, the tail `gzmStopKey` strips from the name, as `.stop-mk-pole` over the marker) and `VehicleLayer` (raw `L.layerGroup` diffed by vehicle id; a fleet over `DENSE_FLEET` = 250 vehicles, i.e. GZM, is canvas dots below zoom 13 and pills only within the viewport padded 25 % above it, `lib/client/fleetMarkers.ts`: every DOM pill is its own composited layer and ~720 of them made each pan frame cost Layerize + HitTest) are imperative escape hatches: keep them imperative (a declarative marker bound to `position` would snap every animated vehicle back to its raw fix on each poll). Every layer takes `map: L.Map` as a prop and mounts inside MapApp's `{#if map}`; keyed polylines/markers go through `KeyedLayers` (`components/leafletLayers.ts`: a known key is updated in place, the rest swept), so a poll never rebuilds a route.
- **Vehicle motion ("Płynny ruch pojazdów").** `lib/client/vehicleAnimator.ts` (one per map, ref-counted) is the ONLY writer of live-vehicle marker positions and arrow angles. It drives the pure dead-reckoning engine `lib/client/vehicleMotion.ts` (along the road shape at the server's cruise speed, capped before the next stop, held while dwelling, smooth catch-up and never visibly driving backwards; tuned with `test/vehicle-motion-sim.test.ts`) from a rAF loop outside Svelte: fleet at a zoom-scaled rate, the tracked bus every frame, paused only while a zoom animation runs (a frame gate, never a sticky flag) and while the tab is hidden. Fleet shapes come from `/api/shapes` (`lib/client/shapes.ts`) at zoom ≥ 13 in view. The per-browser switch is `lib/client/smoothMotion.ts` (`kb:smoothMotion`, on unless the user switched it off); off = passthrough (raw fixes + the 0.9 s CSS glide). `VehicleLayer` ingests every poll even while hidden so tracks stay warm. Traffic (an experiment, never run against live TomTom data: whether it brings the marker closer to real buses in jams is untested): while TripLayer tracks a bus or trolleybus (not a tram, metro or `scheduled` one, smooth motion on) it asks `/api/traffic?lat=&lon=` at the displayed position (`getTrafficSpeed`, `lib/client/api.ts`), again after 500 m or 2 min, and hands the answer to `store.setTraffic`: from the next fix on `plan()` caps `vPred` at that road speed for `trafficMaxAgeMs` (180 s), lowering the pace in a jam and never raising it. The route answers `{speed}` in m/s or null; 404 = traffic not configured, after which the page never asks again; 429 = daily budget spent. Only the tracked bus asks, never the fleet.
- `VehicleLayer` hides its markers while a trip is open; `TripLayer` draws the tracked vehicle itself, matched from the poll by `vehicle.id === trip.execId`, as an animator view on the SAME track as the fleet marker (no jump on open/close). It overrides the track's shape with the drawn route only when that isn't the fleet shape (`trip.shapeId !== vehicle.shape`). KB/MZK trips and connection legs draw server-stored shapes; browser OSRM (`fetchRoute`) is only the fallback while a shape is still `pending`. Trip and line routes share `ROUTE_CASING`/`routeLine`/`routeStop` (`components/leafletLayers.ts`: a 6 px line on a 10 px casing, stops as a ring in the line colour around a `--color-bg` fill, `.route-stop`, moved onto the drawn line by `snapStopsOnto` (`lib/shared/polyline.ts`; a stop > 80 m off it keeps its own point)); the drawn trip, line and journey routes go through `smoothRoute` (same file: stubs and one-vertex spikes cut unless a stop stands at the tip, then a loop under 60 m spliced at the point where the shape crosses itself unless a stop stands on it (an OSRM chunk joint across a roundabout's island, line 92 at Łagiewniki Różana), every bend a curve at most 4 m off the corner; once per route identity, the server shapes stay as stored); the route is pushed `bringToBack()` on every pass (it arrives after the stops and would bury them). An open trip names its stops (standalone `L.tooltip`s, `.route-stop-label`, pane 620 above the markers; the tracked bus has its own pane 630 above them) in the route's colour (`--route-c` on the pane, lifted 50 % toward white in the dark theme): greedy decluttering on each pass and `zoomend` (selected stop, termini, then route order), below zoom 13 only the selected stop and the termini. While a trip is open `StopsLayer` is hidden (as zbiorkom.live does; every pole's marker buried the route at zoom 14+) and the route's circles open their stop (`onSelectStop` = `handleSelectStop`, which closes the trip).
- Deep links: view state lives in the URL (`?stop=`, `?exec=`, `?trip=`, `?map=`; codec in `lib/client/urlState.ts`) via the **plain History API**, written from one effect (a reactive URL store would wake the whole map tree on every `moveend` replaceState). MapApp's single sync effect is the only URL writer; `popstate` is close-only (Android back closes sheets, state stays authoritative). `exec=` and `trip=` are separate params because the two trip-ID spaces can't be told apart heuristically.
- **Line view (zbiorkom.live's route page).** A line hit in the search opens `LineView` (bottom of the sheet stack like NearbyView, counted as an overlay in the URL sync, no URL param). `lib/client/lineRoute.ts` (pure, pinned by `test/line-route.test.ts`) folds today's patterns from `/api/line` into at most two directions by stop order (`splitDirections`: the busiest pattern, then the busiest one that does not run along it; the feeds carry no direction id), merges each direction's patterns into one stop list (`buildDirection`: the busiest is the trunk, another pattern's own stops are "tylko część kursów" rows inserted after the last stop it shares) with every course's departures per row (a pattern's last stop adds none: arrivals), and places the line's live vehicles on it (`placeVehicles`: by trip via `trips`, KB `sched_trip_id`, MZK `mzk:<trip_id>`; next stop = the pattern's stop named `next_stop_name` nearest `next_stop_seq`, the fix projected between it and the one before; a vehicle whose trip is not in the list stays off the diagram). The sheet shows one direction (header swap button) as a rail with the vehicles on it (a tap opens the trip), a row's departures by hour one tap away. While it is open the map shows only that line: `VehicleLayer` gets `line` (`onLine`: name + KB/MZK operator, the operator filter ignored), `StopsLayer` is hidden and `LineLayer` draws the trunk's shape with the merged stops. There is no persistent line filter (the `?lines=` param, `kb:lineFilter` storage and its chip are gone). Shared chip classes are `CHIP`/`CHIP_ON`/`CHIP_OFF`/`chip()` in `components/ui.ts`.
- **Phototrans (fleet card photos + specs).** phototrans.eu's Cloudflare answers a datacenter IP with 403, so the server NEVER fetches it: `scripts/build-phototrans.ts` (`npm run build:phototrans`, run from a home connection, then commit) crawls the current fleet of the operators in its `OPERATORS` table into `lib/phototrans.json` (also compiled into the server; the page parsers stay in `lib/phototrans.ts`, pinned by `test/phototrans.test.ts`), keys `<bb|gzm>:<side number without leading zeros>`. `/api/fleet/<side>` adds `tech` + `photos` from it, plus producer, year, length and propulsion for GZM; the browser hotlinks the 300x200 thumbnails. A GZM fleet number is unique across GZM (each company numbers inside its own block: 50xx-54xx Kłosok, 8xxx the PKS companies, ...), so an `OPERATORS` entry's `range` keeps only that block of a phototrans operator: METEOR's fleet is under IREX Świętochłowice, PKS Gostynin runs PKS Grodzisk and PKS Tarnobrzeg buses. GZM company 2 (ZTM) has no phototrans operator yet.
- **Fleet history.** `/api/fleet/<side>/history` (`?city=gzm`) serves a vehicle's past courses, the card shows them as "Historia kursów"; the card's next-course prediction carries its `source` on the wire.
- **Theme.** Violet brand from the Unisic logo. Dark tokens in `@theme`, light overrides under `:root[data-theme="light"]` (`app/globals.css`). The inline script in `head()` (`app/head.ts`) sets `data-theme` before first paint from `kb:theme` (absent = system, followed live) and owns its own first `<meta id="kb-theme-color">` (the two media-query theme-color tags stay untouched); `lib/client/theme.ts` backs the "Motyw" switch. Hover / fill overlays use `bg-tint/N` (white on dark, black on light), never `bg-white/N`. Route casings carry `className: "route-casing"` (stroke = `--color-bg` via CSS, so they follow a live theme switch); chart colours in `components/brygady/` are `var(--color-*)` tokens, because `VehicleSheet` also opens over the light map. `/brygady` itself stays dark. The default map style follows the theme until the user picks one.
- **Follow me.** The locate button follows the rider (`geoFollow` in MapApp): each fix pans at the current zoom (the first recentres at 15+), a `dragstart` ends it, a tap while following turns the GPS off. Panning pauses while a stop, trip, journey, place or line sheet is open and during a zoom. The heading arrow (`.user-loc-head`) is rotated in place from `GeoPos.heading` (moving fixes only), never by a new icon. No map rotation: Leaflet 1.9.4 has no bearing, and a rotate plugin would break VectorBaseLayer and the animator's pixel math.
- **Map point menu.** Leaflet's `contextmenu` (right-click; long-press: natively on Android, Leaflet's `tapHold` on iOS Safari) opens a `kb-popup` with "Trasa stąd" / "Trasa dotąd" (MapApp `planFromPoint`): the point, labelled after the stop within 300 m, becomes `initialPoint` of ConnectionsDialog, which fills that end on top of the reopened last search, so "stąd" then "dotąd" plans. Vehicle and stop markers (and the canvas dots) don't bubble, so a long-press on one never opens it; a route's stop circles do, and the menu opens at that stop. Result cards and JourneyView count down to leaving (`minsToLeave` in JourneySummary, the first leg's live delay included, "Wyjdź za" when the journey starts with a walk); JourneyView strikes the plan above the live time of a boarding or alighting row more than 60 s off.
- **Connection search, jakdojade-style.** Under the From / To inputs ConnectionsDialog keeps two chips: the time ("Teraz", "Jutro, przyjazd 07:30") and "Opcje (N)" (`activeFilters`); each opens its panel (`panel`: day, leave-at / arrive-by and time; or the Przesiadki / Filtry / Bez / Pomiń / Dojście rows), so the results start right under the inputs. "Przesiadki" is a cap, `maxTransfers` (Bez / do 1 / do 2 / Dowolnie = 0 / 1 / 2 / none): `?maxTransfers=0..4` on `/api/connections`, `RouteQuery.max_transfers` caps the router's rides at `m + 1` (0 = the old direct-only, `direct=true` still works), part of the GZM board memo key. A result is one button, `JourneySummary` (`components/connections/JourneySummary.svelte`, spans only): departure → arrival and the countdown to leaving (`minsToLeave`, else the day), the journey as a strip (`journeySegments` in `lib/client/journey.ts`: rides in their line colour with the number, walks, waits; widths by minutes), the duration, transfers and minutes on foot; a tap opens JourneyView, which shows the same summary above its timeline and leg tabs, so the card has no details of its own. On desktop (`desktop`, 768 px) the dialog is a 400 px panel docked like BottomSheet with no backdrop, so the map stays usable: the hovered or focused card (else the first) goes up through `onPreviewConnection` to MapApp's `preview`, drawn by a second JourneyLayer (`fit={false}`, fleet hidden) after 120 ms of rest. Every result list also goes up (`onResults`, [] while one loads): `JourneyAltLayer` draws each distinct route (`distinctRoutes`, same lines between the same poles, at most 6) muted under the chosen one while the desktop panel or a journey is open, frames them all once per list on desktop, and a click or tap on one (a transparent 22 px hit line, tooltip with lines and times) opens that route's journey (the hovered or open departure for the drawn route). Road geometry is cached per itinerary in a WeakMap (`routeLegs`, settled ones also in `routedNow`), so a hovered card or an opened journey whose route is drawn shows it at once. A stop, bus, line, place or nearby opened from the map or top search closes the panel (`closeConnModal` in each opener). JourneyLayer puts the line's number (`makeJourneyLineIcon`, `.journey-line-pill`) halfway along each drawn leg. A transfer walk is drawn straight until its footpath arrives: `walkRoute` (`lib/client/api.ts`) asks FOSSGIS's OSRM foot profile (`routing.openstreetmap.de/routed-foot`, footways, crossings, underpasses; their policy: at most 1 request/s, so requests leave one per second, attribution + "fix the map" link in `OSRM_CREDIT`), keeps settled paths (`walkRouteNow`, 200), and JourneyLayer redraws when one lands (`walksLanded`); a failure keeps the straight line and asks again on the next draw. Only the drawing; the minutes come from the router. Motion: a journey with `enter` (an opened one, unless its preview was on the map; a list's first preview) draws in, WAAPI in JourneyLayer: each leg sweeps from first to last stop in turn (450 ms split by ride minutes, `pathLength` dash offset), its stops and line number arriving as the line passes, transfer pins at the leg's end, the destination last; the alternatives fade in under it; hovered previews swap at once. Result cards rise in the `.stagger` cascade, the strip wipes in (`.journey-strip`, same 450 ms), the countdown's new minute drops in (`fly`, local to its `{#key}`). Reduced motion: the WAAPI sweep and the `fly` are skipped in code, the CSS ones are cut by the global rule.
- Announcements ("Utrudnienia"): `lib/client/announcements.ts` is a module-level store read through `external()` (`lib/client/external.ts`, same pattern as `favorites.ts`) polling `/api/announcements` (city-aware: `cityUrl`, seen key `kb:annSeen` + `:gzm`) every 15 min; unread = upstream `hash` vs the seen hash in localStorage. Never wire it into the 4 s poll cycle. "Powiadamiaj o utrudnieniach" subscribes through `/api/push/news`; the page re-POSTs its subscription on load (`kb:newsPush` + `:gzm`).
- **Stop announcements ("Zapowiedzi przystanków", GZM only).** In a live, started trip on the `gzm` page TripView's header has a speaker switch (`announcer`, `lib/client/announcer.ts`: an `external()` store, deliberately NOT persisted, off on every page load and on TripView unmount: a browser allows audio only after a user gesture and the tap is that gesture). Leaving a stop says `announceStop(name)` for the next one (`vti` under way) = ZTM's recorded "Następny przystanek" (`p-next`) then the stop's recorded name (`s-<key>`); pulling into it (within 50 m of the pole, straight line, `ANNOUNCE_NEAR_M` in TripView) or standing at it repeats `announceStop(name, false)`, the name alone. Each once per stop (`stopToAnnounce`, `lib/shared/announce.ts`, never one behind the last); turning the switch on applies the same rule at once (the tap is the audio unlock). Clips come from `/api/announce/<name>` (`<name>.mp3`, never part of `out/`; 404 = no recording, then nothing plays, never the phrase alone). One reused `Audio`, the latest call wins (fetches aborted, object URLs revoked), only the phrase blob is kept in JS. Key = `announceKey` (`lib/shared/announce.ts`, pinned by `test/announce.test.ts`): `gzmStopKey` drops the post number, ł -> l, diacritics stripped, lowercased, only `[a-z0-9]`, 94 chars. `scripts/import-announcements.ts <source dir> [dest dir]` (tsx) fills the directory from ZTM's recordings (one directory per municipality, "0 ..." directories are not stops, a request-stop "NZ"/"nż" tail is dropped unless the plain name exists, files over 1 MB skipped).
- PWA updates: `public/sw.js` deliberately does **not** `skipWaiting()` on install: a new SW waits until `PwaRegister`'s toast posts `SKIP_WAITING`, and the reload on `controllerchange` only fires after explicit accept (`clients.claim()` fires it on first install too: an unconditional reload would refresh every new visitor).

## Gotchas

- **An empty `{}` from a passthrough route** (`/api/trip`, `/api/trip_execution`) means "upstream returned nothing" (e.g. vehicle not departed yet), not an error.
- **Two stop ID spaces.** `Stop.urlId` (URL designator, may contain `:`) vs numeric `internalId`/`stopId`. On the frontend, trip time entries match `time.designator → Stop.id` and `time.place_id → Stop.designator`: not interchangeable.
- **Vehicle icons key on line/color/operator/hasHeading, never the heading.** The animator rotates the `.veh-arrow` element in place (unwrapped angles so CSS never spins the long way); `setIcon` rewrites the DOM and replays the pop animation, so putting the bearing back into an icon key makes markers blink on every turn. `TripLayer` reads the live coords in its marker effect through `untrack()` on purpose (raw live coords only seed a new marker).
- **Motion clocks.** The engine runs on one local monotonic clock (`performance.now()`); server epoch seconds (`fix_at`) are mapped via the `X-Server-Time` offset. Never feed `Date.now()` or the KB `timestamp`/`updated_at` (= the server's fetch time) in as a fix time.
- `output/` is generated, gitignored, and eslint-ignored: not stray files.
- 0 vehicles after midnight is normal; buses run ~4:30–22:00.
